| Boundary | Description |
|----------|-------------|
| inbound email body → Gemini extraction | Untrusted external content reaches an LLM — prompt-injection surface |
| n8n → OpenPhone / Resend (outbound) | Customer-facing sends; must be gated by production + emailType + contact checks |
| n8n workflow JSON in git | Secrets must never be embedded |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-08 | Tampering | Prompt injection in email body into Gemini | mitigate | Gemini output is structured-JSON parsed via the 4-strategy extractJson chain; downstream consumers treat fields as data only (no eval, no command construction). Lapham forms bypass the LLM entirely. Accept residual: a crafted email can mis-fill fields → lands in Needs Review for dispatcher, not auto-actioned. |
| T-25-09 | Information Disclosure | API keys in committed workflow JSON | mitigate | All secrets as `{{$env.VAR}}`; verify script greps for AIza/re_/sk- and fails the build if found. |
| T-25-10 | Denial of Service | Auto-reply loop weaponized for spam | mitigate | shouldSkipEmail catches auto-reply subjects; thread-dedup + isDuplicateJob fire before comms; auto-reply gated on non-APT-Internal + production. |
| T-25-11 | Information Disclosure | Coordination email sent to wrong/past tenant (turnover units) | mitigate | emailType !== turnover/inspection gate + tenant-email-presence check before the Resend node. |
| T-25-12 | Spoofing | Forged inbound SMS/webhook (OpenPhone) | accept | OpenPhone integration deferred to Phase 23 entirely — no SMS surface exists in this phase; signature verification designed there. |
| T-25-SC | Tampering | npm installs | accept | No npm packages — all external calls via HTTP Request nodes, no SDKs. |
