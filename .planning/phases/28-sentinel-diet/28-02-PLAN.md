<objective>
Build the single consolidated n8n workflow that replaces the four 24/7 Railway sentinel pollers with one work-hours-only scheduled job, using SENTINEL_INVENTORY.md (Wave 0 output) as the authoritative source of each check's SQL and cadence. One workflow, all Neon-touching checks sequential in one connection window = maximum Neon autosuspend time (RESEARCH.md Architecture Patterns).

This plan also writes the Brandon-runnable importer that POSTs the workflow to n8n with the PTOW Error Handler wired as the errorWorkflow — same import pattern as Phase 25's `phase25_n8n_setup.cjs`.

Purpose: Satisfy SENT-01 (scheduled work-hours runs, no 24/7 polling) and SENT-02 (connect-query-disconnect, no held connections) with zero new infrastructure — existing n8n nodes, existing "Neon Postgres" credential, existing PTOW Error Handler.

Output: `tools/n8n/workflows/phase-28-sentinel-checks.json` (the workflow), `tools/neon/phase28_import_sentinel.cjs` (importer), `artifacts/phase28_02_diff.txt` (diff gate). Brandon imports, activates, runs once, and confirms the Neon graph idles between runs.
</objective>

      c. An IF node (`n8n-nodes-base.if`, typeVersion 1) on `={{ $json.finding }}` === true. The true branch throws (use a Code node that does `throw new Error('SENTINEL FINDING: ' + $json.summary)`) so the workflow's errorWorkflow (PTOW Error Handler) fires and emails Brandon — this reuses the existing alert path with no new email node (RESEARCH.md Anti-Patterns: "Sending alert via email node directly"). The false branch flows to the next check segment (or workflow end).

    For any sentinel marked RETIRE-without-porting in the inventory (e.g. spec-architect with no DATABASE_URL), do NOT add a segment — it is excluded from SENT-01/SENT-02 scope by deletion alone.

    Set the workflow `settings`:

      - `executionOrder: "v1"`.
      - Leave `errorWorkflow` ABSENT in the committed JSON (the importer in Task 2 injects the real PTOW Error Handler id at import time, exactly as phase25_n8n_setup.cjs does — the id is instance-specific and not known at commit time).

    Add a top-level `description` field summarizing: "Consolidated work-hours sentinel checks replacing 4 paused Railway pollers. Sequential checks = one Neon connection window. Activate manually after import." Keep node `position` coordinates spread out (x increments of ~250) so the workflow is legible in the n8n editor.
