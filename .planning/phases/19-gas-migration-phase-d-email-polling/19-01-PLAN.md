# Phase 19 Execution Plan: Migrate Code.js Email Polling to n8n

## Goal
Migrate the `Code.js` email polling functionality (which handles inbound email parsing and lead routing from `workorder@aptmaintenanceinc.com`) to an n8n workflow. This aligns with Phase 19 to reduce GAS dependency and shift core logic to n8n while maintaining existing Neon database syncs. Hard constraint: no new GAS code.

## Scope & Research Summary
- The polling runs in `checkNewLeadEmails()` inside `Code.js`.
- The new logic will live in `tools/n8n/workflows/phase-19-email-polling.json`.
- It requires reading Lapham's Master Directory from Google Sheets.
- It requires calling Gemini via API to parse non-webform emails.
- It will route leads to Neon, leveraging the existing `/api/jobs/sync` endpoint via `DASHBOARD_API_URL` and `DASHBOARD_API_KEY`.
- The untouched GAS functions (`catchUpMissedEmails()`, `resetBackfill()`, `setupBackfillTrigger()`, `archiveOldJobsConfirmed()`, `mineScheduleSheet()`) will remain fully intact.

## Execution Steps

### Step 1: Create n8n Workflow
- Create `C:\PTOW\1_APT_Central_Command\tools\n8n\workflows\phase-19-email-polling.json`.
- **Trigger**: Schedule Trigger or Gmail Node listening to `workorder@aptmaintenanceinc.com`.
- **Logic**: Google Sheets read for Lapham Master Directory, Gemini API call for parsing, and Code node for merging matching address/PropId.
- **Output**: HTTP Request node sending the extracted payload to `DASHBOARD_API_URL/api/jobs/sync` using `DASHBOARD_API_KEY`.

### Step 2: Disable `checkNewLeadEmails` in `Code.js`
- Insert `return; // Migrated to n8n (Phase 19)` at the top of `checkNewLeadEmails()`.
- Do not modify any other code in `Code.js`.

### Step 3: Deployment
- Push `Code.js` via `clasp push --force`.
- Provide the n8n JSON for Brandon to import into Railway/Local n8n.

## Flags & Gates
- **Cross-System Writes & Schema Flag:** The workflow reads from Google Sheets (Master Directory) and writes to Neon via `DASHBOARD_API_URL`. Does Claude Code have concerns about how the data shape matches what `syncJobToNeon` used to do, or should n8n write directly to Neon DB using a Postgres node instead of the API?
- **Column Indexes Flag:** The Google Sheets node in n8n will read the Master Directory. If column indexes move, this will break.
